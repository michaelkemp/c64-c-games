# o-come-all-ye-faithful-c64

A 3-voice SID arrangement of "O Come, All Ye Faithful" (Adeste
Fideles) -- soprano, alto, and a bass line, no percussion. Sibling
project to `../sid-player-c64` (reuses its SID/note-table plumbing,
see below) but a clean directory because the song data comes from a
completely different pipeline: a real 4-part MIDI, not hand
transcription.

## Where the notes came from

`../sid-player-c64` started from a screenshot of printed sheet music
and hand-read the notes off it. That was tried here too, first --
pixel-measuring staff-line positions on `reference/o-come-all-ye-
faithful.png` to identify noteheads -- but a phone-photo-resolution
hymnal scan turned out to be too unreliable to get right note-by-note
without excessive back-and-forth (see git history/conversation for
the abandoned attempt). Instead, this arrangement is generated from
`reference/o-come-all-ye-faithful-keyboard.mid`, a real 4-part (SATB)
keyboard MIDI realization of the hymn in G major.

`tools/gen_pattern.py` reads that MIDI and, for every sixteenth note,
takes the **highest**, **second-highest**, and **lowest** of the 4
simultaneously-sounding voices as soprano/alto/bass. That last choice
is deliberate: in a couple of spots the written bass rests (or the
tenor briefly sits below it), and "lowest sounding pitch" picks up the
tenor automatically right there -- which is exactly the "use the tenor
part to fill in the couple of bars where bass rests" arrangement asked
for, without needing to special-case those measures by hand. Soprano
and alto never need a fallback since all 4 parts are present
throughout.

The MIDI's one musical pass is 20 measures (320 sixteenth-note rows);
it repeats that same pass a second time in the file for verses 2-3
(same tune, different words, which don't matter to an instrumental
SID rendition), so `gen_pattern.py` only emits the first pass --
`main.c`'s infinite loop repeats it anyway.

Regenerate `src/pattern.c` after changing the MIDI or the extraction
logic with:

```
make pattern    # needs `pip install mido`
```

## What's reused from sid-player-c64, and what's different

Reused as-is: `src/sid.h/.c` (SID init/envelope/note-on/off wrapper),
the note-table generation approach, and `main.c`'s frame-timed
`wait_frame()` idiom.

Different:

- **`src/note_table.h/.c`** covers C2-C6, not C3-C6 -- this
  arrangement's bass line dips to G2 at the final cadence, below
  sid-player-c64's Jingle Bells bass. Both are generated by
  `tools/gen_note_table.py` (now parameterized to emit either file;
  `python3 tools/gen_note_table.py h` / `... c`).
- **`src/pattern.h`**: rows are a sixteenth note, not a quarter note
  (`ROW_FRAMES=7`, not 24) -- this arrangement, pulled from a real
  performance, actually has eighth/sixteenth-note motion, not just
  quarters. `PATTERN_LENGTH` is `unsigned`, not `unsigned char`: 320
  rows doesn't fit in a byte.
- **3 voices, no percussion** -- `pattern_row_t` is `{soprano, alto,
  bass}`, no `drum` field, and `main.c` has no noise-channel
  kick/snare time-sharing logic. Simpler because it wasn't asked for
  here, not because it's an improvement on sid-player-c64.
- **`src/pattern.c` is generated, not hand-authored** -- see above.

## Build

```
make run
```

Builds `build/hymn-player.d64` and launches it in VICE (`x64sc`),
autostarting straight into the tune.
