# sid-player-c64

The goal this is working towards: something like Commodore's old
Christmas demos, where each song lived as its own file on a disk, with
a PETSCII picture on screen while it played and a new song/image
loaded in between. That's a few separate pieces (SID playback, PETSCII
display, per-file loading off a `.d64`) — this directory is the first
one: proving the SID chip can play a real, correctly-pitched,
correctly-timed, multi-voice arrangement from C, with nothing
hand-waved.

## What's here

A 3-voice arrangement of "Jingle Bells" (melody, a harmony a third
below, and a bass line) plus a simple kick/snare percussion pattern,
looping forever:

- **`src/note_table.h/.c`** — SID voice frequency-register values for
  three-plus chromatic octaves (C3-C6), generated by
  `tools/gen_note_table.py` from the standard 12-tone-equal-temperament
  formula and the PAL C64's ~985.25kHz clock, so nothing at runtime
  needs float math to turn a note into a register write.
- **`src/sid.h/.c`** — thin SID init/envelope/note-on/note-off wrapper
  around cc65's `<c64.h>` `SID` struct, generalized over
  `struct __sid_voice *` so it works for whichever of the 3 voices is
  calling it.
- **`src/pattern.h/.c`** — the arrangement itself: a hand-transcribed
  array of rows, one per quarter note, each row giving all 3 voices'
  notes (or `HOLD`/`NOTE_REST`) plus that row's drum hit, if any.
  Authored content, not generated — see the comment in `pattern.c` for
  the harmonization approach (diatonic thirds, I/IV/V bass) and why
  that's a deliberate difference from `note_table.c`.
- **`src/main.c`** — `wait_frame()` waits for the VIC raster to reach
  line 250 and leave it again, giving one tick per screen refresh
  (~50Hz PAL) with no CIA timer or IRQ needed for a single fixed
  tempo — same idiom `asteroids-c64-simple/src/main.c`'s swap-timing
  comment describes, just repurposed to drive the tempo here.
  `play_row()` holds each voice's gate open for a row's duration minus
  a short gap, then releases it, so repeated same-pitch notes are
  heard as separate notes rather than one continuous tone.

### Why percussion sounds like it's "stealing" the bass voice

SID only has 3 voices, and this arrangement wants 3 melodic parts
*and* drums. Rather than dropping to 2-part harmony for a dedicated
drum voice, voice 3 does double duty: on a beat with a drum hit,
`play_row()`/`play_drum()` fire a short noise burst on voice 3 first,
then resume (or start) that beat's bass note for whatever's left of
the row. The bass note briefly re-attacks right after every drum hit
as a result — an audible, deliberate trade-off, not a bug.

The kick/snare difference is pure noise-channel trickery, not two
different waveforms: SID clocks its noise generator's LFSR off the
same frequency register a tonal waveform uses for pitch, so a low
value there reads as a duller, lower thump and a high one reads as a
brighter, hissier hit. Both use `WAVE_NOISE`; only `KICK_FREQ` /
`SNARE_FREQ` (and their envelopes) differ. See `main.c`.

## Deliberately not here yet

- **PETSCII art** on screen while the song plays.
- **Loading a song from disk** — the arrangement is a compiled-in
  table, not a file `main.c` reads at runtime. The "one song per disk
  side" behavior the original demos had needs that piece before it's
  possible.
- **More than one song** — `pattern.c` has exactly one arrangement.

Each of those is a reasonable next slice, same way `hires-bounce` ->
`vector-scene` built up one proven piece at a time rather than
attempting the full demo in one step.

## Build

```
make run
```

Builds `build/sid-player.d64` and launches it in VICE (`x64sc`),
autostarting straight into the tune.
